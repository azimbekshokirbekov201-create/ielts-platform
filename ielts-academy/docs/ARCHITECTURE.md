# IELTS Academy architecture

The existing Next.js Route Handlers validate request bodies with Zod and keep their `{data}` / `{error}` response contracts. Runtime access goes through `src/server/local/client.ts` and `engine.ts`, using Prisma's JavaScript engine and a local SQLite driver. The small query adapter preserves the existing server query shape and nested response projections; Supabase SDK types remain for compatibility, with no network calls to Supabase in the active runtime.

Prisma models account identity, hashed sessions, rate limits and durable domain entities. Domain entities are validated JSON records keyed by `(kind,id)`, preserving the original snake_case API fields. Central transactional services enforce parent links, content freezing, ownership, reviewer assignments, role changes, deadlines and grading. SQLite does not provide PostgreSQL RLS: the server boundary is authoritative and database files must never be public. This document storage favors local contract compatibility; large deployments should normalize/index their domain queries before scaling. Historical normalized Supabase SQL remains available for a future explicit migration.

Registration creates an account, Student role, profile and preferences atomically. Scrypt uses an independent salt, N=131072, r=8, p=1. Random 256-bit session tokens are sent only as HttpOnly, SameSite=Lax cookies; only their SHA-256 digests are stored. Password changes invalidate other sessions. Roles and teacher assignments are read from SQLite on each request. There are no sample accounts, public role setters, or browser-authoritative results.

Only administrators read private answer keys. Grading normalizes whitespace/case and applies question word limits and administrator-provided conversion thresholds. No conversion means a real raw score with a null band. Attempts enforce server deadlines, ownership and idempotent submission. Used objective/subjective content and mock structures are frozen except publication state. Mock sections require sequential completed work owned by the same student and started after the mock; Writing Task 2 has double weight, and all subjective grades must exist before an overall estimate appears.

Uploaded files stay under `private-uploads`, outside Next's public directory. Every read requires a session and ownership, published-content access or assigned-teacher/Admin permission. Paths are constrained and uploads cannot overwrite files. Files are checked against MIME signatures and size limits. Signed-link API fields remain compatible, but local URLs rely on the session instead of a public signed token.

AI remains optional, disabled initially and gated by consent and transactional daily quotas. Teacher reviews override estimates; speaking transcript feedback makes no audio-based scoring claims. No provider error is replaced with synthetic feedback.

The setup script applies checksummed versioned SQLite SQL transactionally, seeding only configuration and an achievement definition. The existing Supabase migrations are untouched. Both databases require an explicit export/import plan if switching later. The UI and legacy reference components remain in the same repository; active screens use real APIs and do not use demo data.
